# Build workflow

The build is automatic. From **PowerShell** in this dir:

```powershell
cd C:\ESPHome_Projects\Crowpanel_7.00_ESP32-P4

esphome compile test_dynamic_component.yaml --device COM47
esphome upload  test_dynamic_component.yaml --device COM47
esphome logs    test_dynamic_component.yaml --device COM47
```

That's it. No wrappers, no env vars to remember, no scripts to invoke
on a happy path. ESPHome handles dependencies, the linker, and the
flash.

> **Use PowerShell, not Git Bash.** The IDF's `idf_tools.py` refuses
> to run when it sees `MSYSTEM` / `MSYS*` in the env, and Git Bash
> sets those by default. If you have to run from bash, use
> `cmd //c "esphome compile ..."` and unset the leaks first
> (see [feedback_espidf_gitbash](../.claude/memory/) for the batch-file
> pattern).

## When a build fails

Walk the list, top to bottom. Stop at the first step that fixes it.

| # | Try this                                                | Then                                  |
| - | ------------------------------------------------------- | ------------------------------------- |
| 1 | `esphome clean test_dynamic_component.yaml`             | retry the build                       |
| 2 | `esphome clean-all test_dynamic_component.yaml`         | retry the build (5+ min cold compile) |
| 3 | `.\bootstrap-build.ps1`                                 | retry the build                       |
| 4 | Power cycle the panel (hold BOOT, tap RST)             | retry the build                       |

Step 3 is the recovery for `fatal: not a git repository` errors
from the IDF's dep resolution. The script is idempotent — running
it on a healthy build dir is a no-op.

**Never:**
- `rm -rf C:/esphome_tdd` — destroys the `.git` dir the IDF needs
- `git init C:/esphome_tdd` — only `bootstrap-build.ps1` should do that
- edit `C:/esphome_tdd/CMakeLists.txt`, `sdkconfig`, partition
  files, or anything else under that tree — they're all
  auto-generated by ESPHome. If you find yourself editing one of
  them, you're solving the wrong problem (fix the YAML or the
  component, not the generated file).

## What's in this project (for context)

- `test_dynamic_component.yaml` — the only buildable config; uses
  the local external component at
  `C:/ESPHome_Projects/esphome_dynamic_entity_discovery/components/`
- `bootstrap-build.ps1` — one-time setup + recovery for the
  out-of-project build dir at `C:/esphome_tdd`
- `secrets.yaml` — wifi + HA token, not committed
- `testing/bft.py` — build + flash + log + test harness
- `testing/run_tests.py` — web-API-driven UI test suite
- `testing/logs/` — timestamped build + device logs (never deleted)
- `testing/screenshots/` — timestamped screenshots (never deleted)

## Why the build path is outside the project

`build_path: C:/esphome_tdd` is set in the YAML because the IDF
linker command line on Windows can exceed the 32k char
`CreateProcess` limit when the absolute paths to source files
get long. A short build path keeps the linker happy. The trade-
off: the IDF's dep resolution runs `git rev-parse` against the
build dir, so it has to be a git work-tree. `bootstrap-build.ps1`
makes that one-time setup permanent.
